# 转换流程

线索转客户（可同时创建商机）。转换后自动补全联系人的电话和邮件。

---

## 步骤 1：确认转换方式

用 `page lead` 一次性定位线索并获取完整字段（姓名、手机、产品、区域等），**避免遗漏已有信息反复询问用户**。

```bash
cordys.sh crm page lead '{"keyword":"<线索关键词>","current":1,"pageSize":5,"viewId":"ALL"}'
```

- 找到 → 从返回的 moduleFields 中提取已有字段
- 未找到 → 告知用户，停止
- 多条 → 列出候选，问用户确认哪条

> **只调一次 `page`，不要再用 `search`、`get` 等命令重复查。**

问用户：只转客户，还是同时创建商机？

## 步骤 2：补全目标模块必填字段

转换 API 不校验目标模块必填字段，缺的会留空。**必须在转换前收集齐全，不得跳过。**

校验方式：直接读取以下文件（不要搜索），比对线索已有字段，找出缺失项：

- 只转客户 → 读 `references/forms/account.md`
- 同时创建商机 → 读 `references/forms/account.md` + `references/forms/opportunity.md`

### 自动继承（不要再问用户）

线索中已有的字段直接继承到客户/商机，包括但不限于：客户名、区域、行业、来源、线上来源详情、省市（代码原样传递，如 `3413-`）、产品。

### 商机名称命名规则

按 `sop/inference-rules.md` 中"商机名自动生成"规则生成，在收集缺失字段时一并展示给用户确认。

### 缺失字段

不在线索中的字段即为缺失项，**必须问用户提供后才能执行转换**。

客户必填字段：
- **类型** — 默认"最终客户"（可选值：最终客户、代理商），用户未指定用默认，展示确认时可改

> 例外：**关键决策人（KP）** 可在转换后补充，因为联系人是转换时才创建的。

### 询问格式（固定模板）

收集缺失字段时，统一用以下格式向用户确认：

```
请补充以下信息：

1. 金额：（预计合同金额）
2. 结束日期：（预计签约日期，如 2026-12-31）
3. 服务类型：订阅 / 授权 / 服务 / 维保 / 一体机
4. 业务机会类型：新购 / 续费 / 维保 / 扩容

以下字段已设默认值，如需修改请说明：
- 客户类型：最终客户（默认）
- 签约类型：飞致云直签（默认）
- 最终用户全称：同线索公司名（默认）

商机名称将自动生成为：{简称}-{产品}-{年份}-{服务类型}{业务机会类型}
示例：东方测试-JS-2026-订阅新购
```

> 一次性列出所有待补充项，不要分多轮逐个询问。用户回复后即可执行。
>
> **条件必填**：按 `references/forms/opportunity.md` 的「条件必填」列判断。如签约类型选了代签类，「报备号/代签方名称」变必填，须追加索取后才能提交。

## 步骤 3：执行转换

**提交前必须先展示完整表单给用户确认**。用以下格式列出所有字段：

```
请确认以下信息，确认无误后回复"确认"或"提交"，需要修改请直接说明：

【转换内容】只转客户 / 同时创建商机

【客户】
| 字段 | 值 |
|------|-----|
| 客户名 | xxx |
| 类型 | 最终客户 |
| ... | ... |

【商机】（如同时创建）
| 字段 | 值 |
|------|-----|
| 商机名 | xxx |
| 金额 | xxx |
| ... | ... |

【联系人补全】
| 字段 | 值 |
|------|-----|
| 电话 | xxx |
| 电子邮件 | xxx |
```

> 用户确认后才执行转换命令。如果用户要求修改某些字段，更新后再次展示确认，不要直接提交。

将所有收集到的字段一次性传给转换命令，云端自动完成：转换 + 联系人补全 + 商机字段补全。

```bash
cordys_ext.sh transform '{"clueId":"<线索ID>","oppName":"<商机名>","contactName":"<联系人姓名>","phone":"<手机>","电话":"<座机>","电子邮件":"<邮箱>","类型":"最终客户","金额":50000,"有效合同额":50000,"结束日期":"2026-08-30","签约类型":"飞致云直签","最终用户全称（工商可查）":"xxx公司","报备号/代签方名称":"无"}'
```

参数说明：
- `clueId`（必填）：线索 ID
- `oppName`：商机名称，传了就同时创建商机，不传则只转客户+联系人
- `contactName` + `phone`：用于转换后定位联系人并补全缺失字段
- `类型`：客户类型，默认"最终客户"（可选值：最终客户、代理商）
- `电话`、`电子邮件`：补充到联系人
- 其余商机字段（金额、结束日期、签约类型等）：云端自动补全到新商机

> 转换成功后无需再搜索客户/商机/联系人来验证，`code: 100200` 即为全部完成。直接告知用户结果。
