# 👁 内置视图与自定义视图（viewId）

决定 `viewId` 时读本文件。每个模块的官方内置视图与实例自定义视图都维护在 `references/forms/{module}.md` 的「视图目录」：官方项由 Skill 静态维护，自定义项由 `cordys_ext.sh sync` 从该模块 `/view/list` 自动刷新；`contract/business-title` 没有 `/view/list`，只有内置视图。不同模块不得共用一张假定一致的视图表。

## 1. 匹配流程

```
1. 读取目标模块 forms 的「视图目录」
2. 应用角色 profile 的权限上限，禁止越权扩大
3. 按 core/role-engine.md §2.4 解析用户明确范围：本人→SELF/当前 owner，具体人→该 owner，团队/部门→部门及子部门
4. 用户未指定范围时，才应用角色默认范围
5. 官方视图语义（"我的客户""协作客户""成交商机"）直接匹配该模块内置项
6. 用户明确说"视图""打开/切换到某视图""按某视图统计"，或用引号引用已有名称 → 精确匹配实例自定义视图
7. 用户未说"视图"时，去掉不改变业务含义的查询外壳（"请/帮我/麻烦""看下/看一下/查看/查询/查一下/列出""给我看看"）、首尾引号、空白和句末语气词；剩余文本与**唯一且已启用**的自定义视图名称完全一致时，也直接使用该 viewId
8. 精确同名命中后，不再从视图名称拆出部门、时间等 conditions 重复构造；视图内部条件由 Cordys 负责。只叠加 profile 强制权限条件，以及用户在视图名称之外明确追加的额外筛选
9. 多个已启用视图同名 → 列出候选让用户确认，不猜 ID；只有禁用视图同名 → 不使用该视图，按普通业务条件处理并简要提示视图已禁用
10. 仅包含、部分重合、同义改写或模糊相似 → 仍构造字段 conditions，不猜 viewId，也不静默退回 ALL
```

## 2. 典型语义映射

| 用户说 | viewId |
|--------|--------|
| "全部线索" / "所有线索" | profile 允许全量时才用 `ALL`；销售角色仍为 `SELF` 并说明范围 |
| "我的线索" / "我负责的线索" / "我的客户" | `SELF` |
| "我有哪些超过 7 天没跟进的线索"（经理也一样） | `SELF`；时间条件另行构造，不加 `departmentId` |
| "我的团队 / 我的部门有哪些线索" | 不是 SELF；经理使用 `ALL` + 部门及子部门条件 |
| "协作客户" | `CUSTOMER_COLLABORATION` |
| "成交商机" | `OPPORTUNITY_SUCCESS` |
| "打开'本月新线索'视图" | 精确匹配 lead forms 的实例自定义视图名称 |
| "看下销售三部本周新增线索"，且存在唯一启用的同名视图 | 去掉"看下"后完全同名，使用该自定义 `viewId`，不重复拼部门和本周条件 |
| "看本月新线索"，且不存在完全同名视图 | 按线索创建时间构造本月条件，不因部分相似而猜自定义视图 |

自定义视图可以缩小查询口径，不能取消当前 profile 的 SELF/owner/部门强制范围。
