# 查询生成引擎

本文件是所有 CRM 列表、统计、排名和分布查询的统一编排入口。它不提供固定看板模板，也不规定用户必须查询哪些指标；它只保证自然语言、业务字段与最终请求一致。

## 1. 查询生成顺序

1. **保留用户原始语义与范围**：先判断用户指定的是本人、具体负责人、团队/部门还是公司，再判断问的是当前状态还是某段时间内发生的业务事件；不要用角色默认范围覆盖用户明确范围，也不要看到“本周复盘”就给所有指标机械追加 `WEEK`。
2. **确定模块与业务事件**：例如“新建商机”是商机创建，“赢单”是商机结束，“实际回款”是资金到账，“录入回款”是记录创建。
3. **加载模块事实**：确定模块后，读取 `references/forms/{module}.md`，取得真实字段名、类型、选项值、业务时间口径与该模块的官方/自定义视图目录。构造非空 `conditions` 或统计时必须使用其中的字段事实。
4. **加载操作符契约**：读取 `core/cli-reference.md`，按真实字段类型选择 operator/type；不得凭记忆填写。
5. **合并范围约束**：先遵守当前 profile 的权限上限，再使用用户明确指定的范围；只有用户未指定范围时才应用 profile 的 SELF、部门及子部门或全公司默认值。用户措辞不能越权，角色默认值也不能扩大用户明确指定的较小范围。
6. **执行确定性校验**：CLI 会依据 `references/field-schema.json` 校验字段、type、operator、value 形状和已知枚举。CLI 对不改变语义的常见外层形状错误会先自动归一化；若退出码为 0 且响应 `code=100200`，stderr 中的“已自动归一化/无需重试”只是处理说明，直接消费响应，禁止重跑。真正失败时只按错误指出的字段、当前值形状和目标形状修改一次，不得先读脚本、发无条件探测查询或绕过校验调用裸接口；修正后仍失败才停止并报告原始错误。
7. **只依据真实响应作答**：必须读取命令 stdout 中的响应与数值；只有“运行成功”而没有响应内容，不得声称“数据齐了”或生成数字结论。
8. **保持输出边界**：直接读取 CLI 的 stdout JSON、stderr 和原始退出码。禁止在 CLI 输出后接 `| head`、`| python`、`| grep`，禁止 `2>&1`、`2>/dev/null` 或临时文件二次解析；这些写法会掩盖上游失败、污染 JSON，或触发 Git Bash/Windows 路径与编码差异。查询只使用两类命令：看记录或数量用 `page`，对命中范围内全部记录计算用 `page-summary`。

### 池模块术语锁定（先于池名匹配）

- **术语硬映射：`线索池` = `pool/lead`；`公海` = `pool/account`。** 线索池装共享线索，公海装共享客户，两者不是同义词。
- 先根据用户明确说的“线索池”或“公海”锁定模块，再请求对应的 `/pool/lead/options` 或 `/pool/account/options` 匹配池名。不同模块允许存在同名池；同名不能改变已经锁定的模块，也不能作为跨模块兜底。
- “东区公海”默认表示 `pool/account` 中名为“东区”的池；“东区线索池”默认表示 `pool/lead` 中名为“东区”的池。只有“公海里区域是东区”这类明确字段表达才把“东区”当记录条件。
- 目标模块没有匹配池或返回空池时，按该模块真实结果回答；不得改查另一模块，不得把输出写成“线索池（公海）”。

### 1.1 查询范围意图（先于角色默认值）

| 用户语义 | 查询范围 |
|---|---|
| “我的 / 我负责的 / 我名下的 / 归我的”业务记录；“我有哪些 / 我有多少”线索、客户、商机等 | 在 profile 允许该模块的前提下使用模块 `viewId:SELF`；无 SELF 时用 `owner=当前用户 userId`；不加部门条件，不展开部门 |
| “我的团队 / 我的部门 / 我的下属 / 我们部门 / 团队 / 部门” | 组织范围；经理使用本部门及全部子部门，不得误判为 SELF |
| 明确指定某成员 | 在角色授权范围内使用该成员 `owner=userId` |
| 未出现本人、具体人、团队/部门或公司范围 | 应用当前角色的默认范围 |

角色定义的是权限上限和缺省范围，不是对用户原话的改写。例如经理问“我有哪些超过 7 天没跟进的线索”，两次 `latestFollowUpTime` 查询（`LT` 与 `EMPTY`）都必须使用 `viewId:"SELF"`，不能改写成 `viewId:"ALL" + departmentId`。

### 1.2 视图意图判定

- 官方视图语义（如“我的客户”“协作客户”“成交商机”）按目标模块 forms 的「官方内置视图」直接映射。
- 用户明确说“视图”“打开/切换到某视图”“按某视图统计”，或用引号引用已有名称时，才按 forms 的「实例自定义视图」精确匹配；只允许唯一命中，未命中不得静默退回 `ALL`。
- “本月新线索”“即将到期合同”“三天未跟进客户”等可直接表达成字段条件的普通查询，未出现上述视图引用信号时按业务条件处理，不因名称相似而套用自定义视图。
- 自定义视图可以缩小查询口径，不能扩大当前 profile 的强制范围；必要时继续叠加 SELF、owner 或部门及子部门条件。

## 2. 存量与期间事件

- “当前、现有、进行中、阶段分布、管道”通常是**截至当前的状态**；除非用户明确限定创建期或结束期，否则不自动追加时间条件，输出时标注“截至当前”。
- “本周新增、本月赢单、今年签约、今日回款”是**期间发生的事件**；时间条件必须落在该事件对应字段，而不是统一使用 `createTime`。
- 回款记录尤其要区分：默认“本月回款/回款多少/回款排名”是资金实际发生，必须使用 `contract/payment-record.recordEndTime`；`createTime` 只回答“本月录入了哪些回款记录”，且只走 `crm page` 明细口径。CLI 会在统计请求中拒绝回款 `createTime/updateTime`。
- 同一句话可以同时包含两种口径，例如周复盘中的“本周赢单”与“当前进行中管道”；分别构造查询，不强求条件完全相同。

具体事件对应字段和状态集合只在 `references/forms/{module}.md` 维护，本文件不复制，避免形成第二套业务事实。

## 3. 硬约束与可覆盖默认

- 字段真实类型、合法操作符、枚举 value、角色权限属于硬约束，任何上下文都不能覆盖。
- forms 中的默认业务口径可被用户明确措辞细化：例如默认“回款”按实际回款时间，用户明确问“本周录入的回款记录”时才改用记录创建时间。
- 语义仍不明确且不同选择会显著改变结果时，先向用户说明歧义并询问；不要用一个貌似合理的数字掩盖歧义。
- `field-schema.json` 只负责技术契约，不决定“用户想查什么”；schema 对未知模块/字段的警告不是正确性证明，应先同步表单或核对 forms。
- `crm page` 只查询一页，默认 `pageSize` 为 `30`；纯计数传 `pageSize:1` 读取 `data.total`。`crm page-summary` 固定每页 `500` 条自动翻至 `data.total` 并在进程内流式聚合，只返回合计和有限分组摘要。完整全量倾倒和运行机器本地文件导出不作为技能能力；大量明细只能通过 `page` 按页查看或增加筛选条件。

## 4. 结果核验

- 分组/排名结果必须同时读取合计与各组 count；分组之和与合计不一致时停止下结论。
- 阶段集合必须互斥；“进行中”等排除哪些终态，以对应 forms 的业务术语为准。
- 商机“赢单/输单/成交”必须按 forms 使用 `expectedEndTime`；`actualEndTime` 只是可查询技术字段，不得因 schema 放行就把它当业务成交时间。
- 明确自然日区间必须先运行 `cordys.sh crm date-range <开始日> <结束日>`，将返回的 UTC+8 闭区间用于 `BETWEEN`；禁止用 `CST` 或宿主机默认时区手算时间戳。
- 零结果先检查字段、operator、枚举 value、时间字段和范围是否真实生效；不得随意换字段反复试到出现数据为止。
- `IN/NOT_IN` 的 `value` 即使包含多个选项，也不会改变字段类型：`stage` 的 schema 是 `SELECT`，排除成功/失败时仍写 `type:"SELECT"`；只有表单字段本身为 `SELECT_MULTIPLE` 才写该类型。
- 输出统计结论时，至少能说明模块、范围、业务时间口径以及“截至当前”或具体期间。
