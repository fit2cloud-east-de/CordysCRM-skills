# 查重流程

查重通过 `cordys_ext.sh check` 调用。它按客户名和/或手机号并行搜索线索、线索池、客户、公海、商机、联系人 6 个分类；任一分类查到记录，就统一提醒用户“可能存在冲突”。

查重判断不区分：

- conflict / warning
- 产品是否重复
- 负责人是本人还是他人
- 商机是否关闭

---

## 调用方式

```bash
cordys_ext.sh check '{"客户名":"<公司名>","手机":"<手机号>"}'
```

参数说明：

- `客户名`：客户名或手机号至少填一个；给了人名也放这里
- `手机`：客户名或手机号至少填一个；只给手机号也能查
- `产品`：不参与查重，无需传入。用户话语中的产品简称仍可用于识别这是查重意图，但不能用于缩小结果或改变判断

查重会执行以下搜索：

- 线索：客户名、手机号
- 商机：客户名、手机号
- 客户：客户名
- 联系人：客户名、手机号
- 线索池：客户名、手机号
- 公海：客户名

同一分类中，客户名和手机号命中的同一条记录按 ID 去重。

---

## 返回格式

```json
{
  "display_order": ["线索", "线索池", "客户", "公海", "商机", "联系人"],
  "info": {
    "线索": [],
    "线索池": [],
    "客户": [],
    "公海": [],
    "商机": [],
    "联系人": []
  },
  "judgment": {
    "hasMatches": true,
    "message": "查到相关记录，可能存在冲突，请核对"
  }
}
```

判断只看 `hasMatches`：

- `true`：6 个分类中至少一个非空。统一输出 `⚠️ 查到相关记录，可能存在冲突，请核对`
- `false`：6 个分类全部为空。输出 `未查到相关记录`

`info` 中仍保留全部命中记录，供用户核对以及后续写入复用 ID。

任一已发起的分类查询失败时，脚本返回 `error`，不得用其余空结果判断 `hasMatches=false`，也不得继续创建；应提示用户稍后重试查重。

## AI 展示与写入指引

- 必须按模板完整输出 6 个分类，无记录的分类写“无”
- null 字段显示 `-`
- 分类顺序必须为：线索 → 线索池 → 客户 → 公海 → 商机 → 联系人
- 不得再自行划分“冲突”与“警告”，也不得根据产品、负责人或商机阶段改变 `hasMatches`
- 主动查重时只客观提醒“可能存在冲突”，不得宣称已确认重复
- 创建前 `hasMatches=true` 时，展示命中记录并询问用户是否继续；用户明确继续后才可创建
- 不得在模板之外追加背景评价或个人判断
